枝 `feat/12-frame-notices`（`5630008`）を `cargo build --release`。操作は Windows 側の本物の入力（PowerShell の SetCursorPos / mouse_event / keybd_event）で行い、見た目は Windows 側の画面キャプチャ（CopyFromScreen）、当たり判定は Windows の WindowFromPoint で取った。X 側は xwininfo / xev / xprop / xclip。

### Alt+F4（訂正と原因）

`xev -id <窓> -event keyboard` を、押下と離しを分けて読んだ。施主の本物のキーボードで 3 回、`keybd_event` で枠とモーダルに各 1 回。どれも同じ並びだった。

```text
KeyPress   Alt_L  state 0x0
KeyRelease F4     state 0x8   （本物のキーボードでは 1〜3 回）
KeyRelease Alt_L  state 0x8
```

- **F4 の `KeyPress` は届かない。** Windows（msrdc）が握り、RAIL の `SC_CLOSE` として Weston に送る（weston-mirror `rdprail.c` の `rail_client_Syscommand_callback` → `request_window_close`）
- その `SC_CLOSE` は遅れて届く。施主の操作: Alt+F4 で消えず、しばらくして線を触ったら消えた（終了コード 0）。施主が触っていない時刻に枠が終了コード 0 で消えた件も、先に送った Alt+F4 / `SC_CLOSE` が遅れて届いたと読める
- `SC_CLOSE` を Windows の窓へ `PostMessage` で直接送ると、枠は 1 秒で終了。モーダルは閉じない
- `WM_DELETE_WINDOW` を X から直接送ると、モーダルは即座に閉じる

### 起動直後に Windows 側へ絵が出ない（再現）

新しい枝で起動した直後、X 側（`import -window`）では描けているのに、Windows 側の画面には何も出ず、線の画素も `WindowFromPoint` に当たらなかった。`xdotool windowmove` で窓を動かすと出た。
