## 4. PR を merge する手順

squash merge（GIT-004）。上から順に。**squash すると次の枝は古いコミットを抱えたままになる**ので、1 本 merge するたびに次の枝を `main` に rebase して base を付け替える。

```bash
# 例: #3 を merge した直後、#5 の枝を main に載せ替える
git fetch origin
git switch feat/4-settings-modal
git rebase --onto origin/main f9de50e        # f9de50e = 直前に merge した枝の先頭（第 1 節の表）
make lint && make test && make conformance   # 載せ替えで壊れていないことだけ見る
git push --force-with-lease
gh pr edit 5 --base main                     # gh が無ければ GitHub の UI で base を main に
```

次の枝は、その次の枝の `--onto` の起点になる。表の SHA を順に使う（#5 の後は `9fe9c95`、#7 の後は `ae967f1`、…）。
PR を Ready にすると CI の `make ci` が初めて走る。**最初の成功を gate-proofs 第 6 節の「まだ証明していないこと」から消し、GIT-001〜003 と QLT-005 を active にする**（CNF-009 が証明行を要求する）。
`main` の ruleset（PR 必須・squash のみ・force push 禁止）は GitHub の設定で、設定したら gate-proofs に記録する（QUALITY_GATES 第 5 節）。

## 7. 施主の雛形（AYANE）への還流点

単体テストでは見えず、Xvfb か実機でだけ出た欠陥。雛形の「実機で見る項目」に足す価値がある（CLAUDE.md 第 8 節）。

1. XFixes は `QueryVersion` を先に送らないと入力 shape が効かない（gate-proofs 8.4）
2. 入力 shape の外へポインタが出ると `MotionNotify` ではなく `LeaveNotify` が届く（11.2）
3. `Drop` が送る `DestroyWindow` は次の `flush` まで届かない（9.2）
4. WSLg は X の入力 shape を見ず、描いた画素（アルファ > 0）だけを当たりにする。Weston の XWM は飾りなしの窓に影を描く（14.2・ADR 0008）
5. 子 shell から起動したプロセスは zombie になり、`pgrep` / `kill -0` が「生きている」と答える。`/proc/<pid>/status` の `State` と `wait` の終了コードで判定する（15.2）
6. 分岐カバレッジは stable の rustc では測れない（`-Z coverage-options=branch`）。規則を書く前に測れるか確かめる（8.2）

## 8. 実機での検証の作法（施主の前回の手順）

- 入力は Windows 側の本物の入力（PowerShell の `SetCursorPos` / `mouse_event` / `keybd_event`）。`SendKeys` の `{RIGHT}` は拡張キー印が無く `KP_Right` になるので、`keybd_event` に `KEYEVENTF_EXTENDEDKEY` を付ける
- 見た目は Windows 側の画面キャプチャ（`CopyFromScreen`）。X の `import` は XWayland では根の窓を撮れない
- 当たり判定は Windows の `WindowFromPoint`。X 側の確認は `xwininfo` / `xev` / `xprop` / `xclip`
- 記録は `docs/quality/wslg-<日付>.md` に置き、gate-proofs に要約する。PNG は手元に残し、リポジトリには Xvfb のものだけ入れる
