## 3. つまずき

| 何が | どう直したか | 教訓 |
| --- | --- | --- |
| hub の WSL で Xvfb が立たない（`/tmp/.X11-unix` が読み取り専用で 1777 にできない） | `Xvfb -ac -listen tcp -nolisten unix` と `DISPLAY=127.0.0.1:98` | WSL では unix ソケットでなく TCP で立てる。手順を gate-proofs 第 50 節に書いた |
| `pkill -f "Xvfb :97"` が自分のシェルを殺した | パターンを含まないスクリプトファイルから `kill $PID` | `pkill -f` は bash -c のコマンドラインにも一致する |
| 字を大きくしたら 150% の論理画素で既定の枠が詰めた表示に落ちた | 全部描ける判定を「縦の数字は横の数字の下から」→「上辺の数字の帯の下から、横の数字と交わらない」に | 判定が過剰に厳しいだけで、設計の衝突ではなかった |
| 比を主モニタで起動時に一度だけ決めていた（ADR 0027 の既知の穴） | #104 で窓が乗っているモニタに従わせた | 「残る穴」に書いた制約は、実機で最初に踏まれる |
| 枠の物理サイズを保ったら論理画素の数字が変わった | 選んだ単位の大きさを保つ設計に改めた（ADR 0029 の決定 3） | 「測った値を保つ」の「測った値」は選んだ単位の値。ブラウザの窓と同じ振る舞いが正 |
| check.yml が `opened` で走らず、draft ↔ Ready の往復が速すぎて 1 度は走らなかった | `sleep 5` を挟む・PR の本文を編集して `edited` で起こす | 走ったかは `gh run list --branch` で head の sha を見て確かめる |
| #103 を draft に落としたまま merge しようとして `still a draft` | `gh pr ready` し直し | `gh pr ready --undo` の後は必ず `gh pr ready` の成功を見る |
| #105 の rebase で `--onto main` の upstream に rebase 済みの枝を指して衝突 | `git rebase --abort` → 元の親 sha（`4269a1c`）を upstream に | 積んだ枝を順に main へ載せ替えるときは、upstream は「rebase 前の親の sha」 |
| #109 の PR 本文が GIT-004 の欄を欠いて `validate-git` が落ちたのに merge が通った | 本文をマージ後に直した | main の ruleset が未設定なので失敗した check でも merge できる（current.md の「残る穴」）。文書だけの PR でも本文は全欄書く |
| squash の件名が `(#Issue) (#PR)` になった（5 本とも） | 直していない | 10-19 の地雷のとおり `gh pr merge --subject` を使うべきだった |
| 起動中の exe に `cp` で上書きできない（Permission denied） | 別のフォルダに置いた（`nene-ruler-pr104-2` / `-3`） | Windows は実行中の exe をロックする |

## 5. 地雷

- **比は起動時だけでなく `WM_DPICHANGED` で変わる。** `RulerController::follow_dpi` が単位に従って枠を伸縮する。X11 には `DpiChanged` を送る所が無い（`Xft.dpi` は 1 つ）
- **`Logical px` の目盛は物理画素に乗らない**（150% で 8 / 7 の交互）。にじまないが不揃いに見える。ブラウザと同じ丸め
- **1.0.0 のパーサは `unit = physical_px` を知らない。** 1.1.0 と 1.0.0 を同じ `%APPDATA%` で行き来すると 1.0.0 が既定に戻る（壊れない）
- **論理画素の高さ 240 で左辺の `150` が下辺の主目盛に重なる**（Issue #46 の判定のまま）。物理画素でも高さ 260 の `250` で起きる既存の穴
- 施主の `Downloads` に試作の exe が 4 フォルダ残っている（`nene-ruler-pr101` / `pr102` / `pr104` / `pr104-2` / `pr104-3`・`1.1.0`）。公開後に消す
