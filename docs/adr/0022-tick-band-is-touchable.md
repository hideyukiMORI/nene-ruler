# ADR 0022 — 目盛の帯を移動の当たり判定にし、目盛の上ならどこでも掴めるようにする

- 状態: 受理
- 日付: 2026-10-18
- Issue: #66
- 影響する規則: FR-002 / FR-017。ADR 0005 の 3（触れる矩形の集合）を改める

## 文脈

ADR 0005 の 3 は、触れる矩形を線の帯・鉤括弧・ギア・数字に限り、目盛は素通しにした。X11 版は入力 shape でそれを守る。

施主が Windows 版（PR #63）で「目盛が実際に描画されているピクセルの所しか hover が効かない」とした（2026-10-18）。`WindowFromPoint` で窓全体を測ると、目盛と目盛の数字の部分（線から内側へ約 30 px）は描いた画素だけが当たり、隙間は下の窓へ抜けていた。Windows の layered 窓は、アルファが 0 でない画素を必ず当たりにするので、素通しのはずの目盛の画素が穴あきに当たる。

施主は推しの「目盛の上ならどこでも掴める」を選んだ。

## 決定

**全部描いた表示（`FrameDetail::Full`）では、各辺の目盛の帯を移動（`HitTarget::Move`）の当たり判定にする。帯は core の `FrameLayout::tick_band` が返し、`hit_regions` の最後（線の帯の後）に並べる。**

1. 帯は線から内側へ、主目盛の先まで。上辺は目盛の数字の下端まで、左辺は最も桁の多い目盛の数字の右端まで
2. 鉤括弧・ギア・数字の当たり判定が先に勝つ。幅と高さの数字は帯の外に置かれている
3. 詰めた表示・線を消した表示は目盛を描かないので、帯も無い
4. X11（入力 shape と下塗り）も Windows（下塗り）も `hit_regions` を写すだけなので、両方が同じになる

## 強制

- **active**: core の単体テスト（1x と 2x の帯の矩形・目盛が帯に収まる・目盛と数字の隙間で移動・鉤括弧が先に勝つ・帯の外の数字の手前は素通し・詰めた表示では帯が無い）
- **planned**: 施主の目視（QLT-013）

## 結果

- 目盛の上ならどこでも掴めて、ポインタも移動の形になる
- 枠の内側で下の窓をクリックできる範囲が、上辺と左辺で約 30 px、下辺と右辺で 12 px 狭くなる
- Windows で目盛の画素だけが当たる穴あきが消える

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 今の仕様のまま、Windows でも目盛の画素を素通しにする | layered 窓はアルファが 0 でない画素を当たりにする。素通しには `WS_EX_TRANSPARENT` をポインタの位置で切り替えるなど、窓の作りが込み入る。施主も目盛の上で効く方を選んだ |
| 線の帯（両側 4 px）を太くする | 目盛の数字の部分まで届かせると外側の余白も広がり、窓が大きくなる |
