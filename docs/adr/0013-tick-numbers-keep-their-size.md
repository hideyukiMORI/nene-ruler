# ADR 0013 — 主目盛の数字は倍率に関わらず 9 px で描く

- 状態: 置換 → [0028](0028-text-in-logical-pixels-and-ticks-follow-the-unit.md)（字の大きさは論理画素 9 で、比で物理画素にする・2026-10-20）
- 日付: 2026-10-17
- Issue: #32
- 影響する規則: FR-003 / FR-016。ADR 0011 の決定 2 のうち「数字の字の大きさ」を、主目盛の数字についてだけ置き換える

## 文脈

ADR 0011 は、数字と通知の字の大きさに UI の倍率を掛けた。2x では主目盛の数字（`50` / `100` …）が 18 px になる。
施主は WSLg で 2x の定規を見て、「目盛の数字はもっと小さく、9〜10 px に」と指示した（2026-10-17）。主目盛の数字は 50 px おきに並ぶので、大きくすると目盛そのものより目立つ。

## 決定

**主目盛の数字の字（9 px）と桁の幅の見積り（6 px）には倍率を掛けない。** 目盛の長さ・目盛と字の隙間・幅と高さの数字（`400 px`）・通知・鉤括弧・ギアは ADR 0011 のまま倍率を掛ける。

## 強制

- **active**: core の単体テスト（2x の主目盛の数字のベースラインが字の高さ 9 px で計算され、左辺の数字の幅が 1x と同じ。縦の数字と通知が左辺の数字と重ならない）
- **planned**: 施主の目視（QLT-013）

## 結果

- 2x でも主目盛の数字は 1x と同じ大きさ。4K の画面では小さいが、施主の指示どおり
- 幅と高さの数字（`400 px`）は 2x のまま大きい。目盛の数字との大きさの差が 1x より広がる

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 10 px にする | 1x の 9 px と同じにすれば、1x と 2x で目盛の数字の見えが揃う。施主の指示の幅（9〜10 px）に入る |
| 主目盛の数字だけ倍率を 1.5 にする | 整数倍率の決定（ADR 0011）から外れる。字だけなら分数でもにじまないが、置き場の見積りが半端な画素になる |
