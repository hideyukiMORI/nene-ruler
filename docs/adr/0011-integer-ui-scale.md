# ADR 0011 — UI の倍率は 1x / 2x の整数で、飾りにだけ掛ける

- 状態: 受理（決定 2 の主目盛の数字の大きさは置換 → [0013](0013-tick-numbers-keep-their-size.md)、モーダルの倍率は置換 → [0014](0014-frameless-single-scale-modal.md)、幅と高さの数字は置換 → [0015](0015-length-numbers-keep-their-size.md)。字の大きさと目盛の間隔は改訂 → [0028](0028-text-in-logical-pixels-and-ticks-follow-the-unit.md)）
- 日付: 2026-10-17
- Issue: #28
- 影響する規則: ARC-001 / ARC-004 / ARC-011。仕様 FR-016 / FR-003 / FR-014

## 文脈

FR-016 は「表示は HiDPI で崩れない。測る値は常に物理画素」とし、倍率の出どころ（`Xft.dpi` か RandR の DPI）と丸め方を「決め打ちしない」のまま置いていた。
枠もモーダルも 1x の定数で描いており、施主の画面（WSLg・4K が 3 枚。RandR では rdp-4 が 3840 px / 600 mm ≒ 162 dpi）では鉤括弧・ギア・数字・モーダルが小さい。

2026-10-17、施主が引き継ぎ書第 3 節の推奨どおり **整数（1x / 2x）** に決めた。分数倍率は 1 px の線や目盛を半端な画素に割り、にじませる。

物差しには、倍率を掛けてはいけないものがある。枠の大きさは測った値そのもので、線と目盛はその目印である。

## 決定

**UI の倍率 `UiScale`（core）は 1x と 2x の閉じた集合で、起動時に一度だけ `Xft.dpi` → `RandR` の dpi → 1x の順に決め、144 dpi（1.5 倍）以上を 2x とする。倍率は飾りにだけ掛け、測るものには掛けない。**

1. 出どころ
   - `Xft.dpi`: ルート窓の `RESOURCE_MANAGER`（`xrdb` が置く文字列）の整数部。ui-x11 の `Display` が読み、`Environment` に添える
   - `RandR`: 物理寸法と同じ出力（主出力、無ければ繋がっている最初の出力）の横の dpi（`ScreenMetrics::dots_per_inch`）
   - どちらも無ければ 1x
2. 倍率を**掛ける**もの: 当たり判定の帯・鉤括弧（腕と太さ）・ギア・目盛の**長さ**・数字と通知の字の大きさと隙間・モーダルの全部品と字・選択の輪・取り消し線
3. 倍率を**掛けない**もの: 枠の大きさ（`FrameSize`）・線と目盛の**太さ**（1 px）・目盛の**間隔**（5 px）。初期の枠の大きさ（400 × 240）も物理画素のまま
4. `FrameLayout` と `SettingsLayout` が倍率を持つ。描く置き場と当たり判定は同じ layout から出る（ARC-001）。UI は `layout.scale()` で字の大きさを決める
5. 2x の初期の枠（幅 400）に収まるよう、枠の通知 `always on top: not supported by this window manager` を `always on top: not supported here` に縮める（モーダルは Issue #23 で同じ文言にした）

## 強制

- **active**: core の単体テスト（dpi の境界 143 / 144・`Xft.dpi` の読み取り・出どころの順・2x の置き場が 1x の 2 倍で、枠の大きさ・線の太さ・目盛の間隔と太さは同じ）、application の単体テスト（`Xft.dpi` と `RandR` から倍率が決まり、窓から枠へ戻すときも 2x の余白を引く）
- **active**: ui-x11 の画素テスト（2x の線が 1 px・2x のモーダルが 640 × 672・2x の通知が右辺の目盛より手前で終わる。旧い文言では落ちる）
- **planned**: WSLg での目視（QLT-013）。記録は gate-proofs 第 20 節

## 結果

得られるもの:

- 4K の画面で、飾りと文字が 1x の 2 倍の大きさで、にじまずに出る
- 測る値は倍率に関係なく物理画素のまま（FR-016 の後半）

失うもの・残る穴:

- **施主の WSLg は今のままでは 1x になる。** `Xft.dpi` は置かれておらず、主出力 rdp-0 の物理寸法は 0 mm（RandR）なので、どちらの出どころも無い。2x にするには `xrdb -merge` で `Xft.dpi: 192` を置く
- 倍率は起動時に一度だけ決める。dpi の違う画面へ動かしても変わらない
- 2x の初期の枠（400 × 240）は、飾りに対して小さく見える。枠の大きさは測る値なので倍率を掛けない
- 字の幅は見積り（`LABEL_ADVANCE_PX` など）に倍率を掛けたもので、フォントによってずれる。当たり判定は今まで通り見積り

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 0.25 刻みなどの分数倍率 | 1 px の線・目盛・帯が半端な画素に割れてにじむ。施主の決定は整数 |
| 3x 以上も持つ | 2x を超える dpi（288 以上）の画面が手元に無く、確かめられない。必要になったら閉じた集合に足す |
| 線と目盛の太さにも倍率を掛ける | 2 px の線は、どちらの画素が端かを曖昧にする。物差しの線は測る位置そのもの |
| 枠の初期の大きさにも倍率を掛ける | 枠の大きさは測った値。起動直後の「400 px」が画面によって 800 px になると、表示と実寸の関係が画面ごとに変わる |
| 窓が乗っている出力ごとに倍率を切り替える | 画面をまたぐたびに窓の大きさが変わり、`ConfigureNotify` と伸縮の扱いが要る。今は起動時の一度だけ（ARC-004） |
