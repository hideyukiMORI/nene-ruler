# ADR 0028 — 字の大きさは論理画素で定め、目盛は選んだ単位で刻む

- 状態: 受理
- 日付: 2026-10-20
- Issue: #102
- 影響する規則: ARC-001 / ARC-004 / ARC-011。仕様 FR-003 / FR-004 / FR-014 / FR-016。ADR 0013 と ADR 0015 を置き換える。ADR 0011 の決定 2 のうち「数字と通知の字の大きさと隙間」と決定 3 のうち「目盛の間隔」を改める。ADR 0027 の決定 7 のうち「目盛の間隔」を改める

## 文脈

字の大きさは UI の倍率（1x / 2x の整数・ADR 0011）から外され、主目盛の数字は 9 px（ADR 0013）、幅と高さの数字は 11 px（ADR 0015）に固定されていた。
10-17 に施主が WSLg の 2x を見て「小さくていい」としたのは、2x で字が 22 px になった状態を見てのことである。
2026-10-20、施主が 150%（144 dpi）の Windows で論理画素の枠を見て「倍率に合わせて数値の文字のフォントサイズも変更しないと読めない」とした。
4K の画面で物理 11 px の字は、ブラウザの 7 px の字と同じ大きさにしか見えない。

整数の倍率は 1 px の線をにじませないための決定で（ADR 0011）、字には要らない。字は分数の大きさでもにじまない。
10-17 の「大きすぎ」と 10-20 の「小さすぎ」は、どちらも**実際の比（150% なら 1.5 倍）を整数に丸めた**ことが原因で、矛盾していない。

施主の整理（2026-10-20）: 「文字のサイズは物理値・論理値どっちを選んでも人間が見たときに同じ大きさに見えるフォントサイズにするべきで、目盛は選んだ方の値に合わせてサイズを変えるべき」。

ADR 0027 が持ち込んだ `DevicePixelRatio`（デスクトップの dpi / 96）がそのまま使える。ブラウザの 11px の字と同じ見た目は「11 論理画素」である。
ADR 0027 は目盛を物理画素のままにしたが（決定 7）、論理画素を選んだ人は開発者ツールの数字で測っているので、目盛の `50` も論理画素の 50 であるべきである。

## 決定

**字の大きさは論理画素で定め、単位の選択に依らず比（dpi / 96）で物理画素に丸める。目盛は選んだ単位で刻み、位置を物理画素に丸める。飾りの整数の倍率と、枠の大きさが物理画素であることは変えない。**

1. `FrameLayout` は `Measure`（単位と比）を持つ。字の高さ（主目盛の数字 9・幅と高さの数字 11・通知 9 と行間 12）と字の幅の見積り（1 文字 7・1 桁 6）は**論理画素**の定数で、`DevicePixelRatio::physical`（四捨五入）で物理画素にする。単位が `Physical px` でも `Logical px` でも同じ大きさ
2. UI は `FrameLayout::tick_label_px` / `label_px` / `notice_px` で字の大きさを決める。ui-x11 と ui-win32 に字の大きさの定数は置かない（ARC-001 / ARC-011）
3. `TickMark::along` は `Measure` を受け、小 5 / 中 10 / 主 50 を**選んだ単位**で刻む。`value` が単位での値（主目盛の数字はこれ）、`offset` が物理画素の位置（`Measure::physical` で丸める）。`Physical px` なら今までと同じ位置と値
4. 左辺の数字の幅は、選んだ単位での高さの値の桁数で見積もる（論理画素なら 150% の高さ 240 は 160 で 3 桁）
5. 全部描ける判定（ADR 0017）のうち「高さの数字は幅の数字の下から始まる」を、「高さの数字は上辺の数字の帯の下から始まり、幅の数字と矩形が交わらない」に改める。字が大きくなると前の判定では 150% の論理画素で既定の 400 × 240 が詰めた表示に落ちたが、縦の数字と横の数字は横に離れていて重ならない
6. 飾り（帯・鉤括弧・ギア・目盛の長さ・取り消し線）は整数の UI 倍率のまま。枠の大きさ・線と目盛の太さは物理画素のまま。設定モーダルは 1x のまま（ADR 0014）

| dpi | 比 | 主目盛の数字 | 幅と高さの数字 | 通知 | `Logical px` の小目盛の間隔（物理） |
| --- | --- | --- | --- | --- | --- |
| 96（100%） | 1 | 9 | 11 | 9 | 5 |
| 120（125%） | 1.25 | 11 | 14 | 11 | 6.25 → 6 / 7 / 6 / 6 … |
| 144（150%） | 1.5 | 14 | 17 | 14 | 7.5 → 8 / 7 / 8 / 7 … |
| 192（200%） | 2 | 18 | 22 | 18 | 10 |

## 強制

- **active**: core の単体テスト（`DevicePixelRatio::physical` の 144 / 120 / 192 dpi と `u16::MAX`・`Measure::physical` が物理画素では換算せず論理画素では比を掛ける・`TickMark::along` が 144 dpi の論理画素で 8 / 15 / 23 / 30 … に乗り主目盛が 75 ごと・`FrameLayout` が 144 dpi で両単位とも 14 / 17 / 14、96 dpi で 9 / 11 / 9、192 dpi で 18 / 22 / 18・論理画素の目盛の数字が 50 / 100 / 150 / 200 で左辺の数字の幅が 27・物理画素は dpi に関わらず同じ位置と値・縦の数字と通知が左辺の数字と重ならない（5 つの倍率と単位の組 × 3 つの高さ）・150% の論理画素で 400 × 240 と 500 × 280 が全部描け、239 と幅 300 では詰める）
- **active**: ui-win32 と adapters-windows は `cargo clippy --target x86_64-pc-windows-gnu -- -D warnings` が 0 件
- **planned**: 施主の Windows（150%）で字が読め、ブラウザの開発者ツールの要素の幅と目盛が合うこと（QLT-013）。記録は gate-proofs 第 50 節

## 結果

得られるもの:

- 150% の画面で字が 1.5 倍になり、ブラウザの同じ大きさの字と同じに見える。200% では 2 倍で、10-17 に 2x で見たのと同じ大きさ
- `Logical px` を選ぶと、目盛の `50` が開発者ツールの 50px と同じ位置になる
- 字の当たり判定も同じ見積りで大きくなり、4K で押せる範囲が広がる（ADR 0015 の「42 × 15 px」の穴が閉じる）

失うもの・残る穴:

- 論理画素の目盛は物理画素に乗らないので、150% では小目盛の間隔が 8 と 7 で交互、125% では 6 と 7 が混じる。線は 1 px のままにじまないが、間隔はわずかに不揃いに見える。ブラウザが CSS px を物理画素に描くときと同じ丸め
- 論理画素の数字は長く（`266.7 logical px` は 16 文字）、字も大きいので、全部描ける枠の下限は物理画素のときより大きい。150% では既定の 400 × 240 が全部描ける最小に近い（高さ 239 で詰める）
- 左辺の主目盛の数字が下辺の目盛に重なることがある（論理画素の高さ 240 の `150` は原点から物理 225 px で、下辺の主目盛の長さ 24 px の中に入る）。判定は枠の底しか見ていない（Issue #46 のまま）。物理画素でも高さ 260 の `250` で起きる既存の穴
- 比は起動時に一度だけ決める（ARC-004）。dpi の違う画面へ動かしても字と目盛は変わらない
- WSLg は `Xft.dpi` を置かないので 1x のまま。字を大きくするには `xrdb -merge` で `Xft.dpi` を置く（ADR 0011 と同じ）

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 字に整数の UI 倍率（1x / 2x）を掛ける（ADR 0011 の元の決定） | 150% で 2 倍になり、10-17 に施主が「大きすぎ」とした状態に戻る。字は分数でもにじまないので整数に丸める理由が無い |
| 字の大きさを 9 / 11 px に固定したまま（ADR 0013 / 0015） | 150% の 4K で読めない（施主 2026-10-20） |
| 字の大きさを選んだ単位で変える（論理画素のときだけ大きく） | 単位は数字の意味を変えるもので、見た目を変えるものではない。物理画素を選んだ人も 150% では読めない |
| 目盛を物理画素のまま（ADR 0027 の決定 7） | 論理画素で測っている人にとって、目盛の `50` が物理 50 px では数字と目盛が食い違う |
| 論理画素の目盛を、物理画素に乗る間隔（150% なら 10 論理 = 15 物理）に変える | 125% では 20 論理 = 25 物理まで粗くなり、倍率ごとに目盛の密度が変わる。丸めで交互になる方が、どの倍率でも同じ密度で読める |
| 枠の大きさを論理画素の整数に吸着させる | 枠の大きさは測った値で、ドラッグは物理画素で動く。`266.7` の端数が気になるなら別の Issue |
| 全部描ける判定を変えずに置く | 150% の論理画素で既定の枠が詰めた表示になり、目盛が消える。縦の数字と横の数字は横に離れていて、前の判定が過剰に厳しかっただけ |
