# ADR 0014 — モーダルは 1x・飾りなしで、閉じるボタンと移動を自前で持つ

- 状態: 受理
- 日付: 2026-10-17
- Issue: #34
- 影響する規則: ARC-001 / FR-009 / FR-010 / FR-015 / FR-016。ADR 0011 の決定 2（モーダルに倍率を掛ける）を置き換える

## 文脈

2026-10-17、施主が WSLg で 2x のモーダル（640 × 560）を見て、次を指示した。

- 大きい。字ももっと小さくてよい
- WSLg が付けるタイトルバー（最小化・最大化・閉じる）は要らない。閉じるボタンは自前で作る
- ダークの背景は `#000000`

枠の窓はすでに飾りなしで、影も窓の種類で消している（ADR 0008）。モーダルは WM に飾りを任せていた。

## 決定

**モーダルには UI の倍率を掛けず、枠の窓と同じ要求で飾りと影を外し、右上の × と、部品の無い所のドラッグでの移動を自前で持つ。**

1. `RulerController::settings_frame` は常に `SettingsLayout::new(UiScale::Single)` を渡す。320 × 280、字は 15 / 12 / 10 px
2. `_MOTIF_WM_HINTS`（飾りなし）と `_NET_WM_WINDOW_TYPE = [_KDE_NET_WM_WINDOW_TYPE_OVERRIDE, _NET_WM_WINDOW_TYPE_NORMAL]` を map の前に付ける。枠の窓と同じ関数（`undecorated::declare_undecorated`）を使う（ARC-001）。`WM_TRANSIENT_FOR` と `WM_DELETE_WINDOW` は今まで通り
3. `SettingsControl::Close` と `SettingsLayout::close_button`（右上・24 × 24）。押すとモーダルだけ閉じる（Esc と同じ）
4. どの部品にも当たらない所を左ボタンで掴むと、WM の `_NET_WM_MOVERESIZE`（移動）で動かす。WM が対応しなければ自前のドラッグ。枠の窓と同じ関数（`undecorated::ask_wm_to_move_resize` / `geometry_of`）と `Drag` を使う
5. 窓の外周に、見えの `border` 色で 1 px の縁線を描く。飾りが無いので、黒い背景がデスクトップの暗い所に溶けるのを防ぐ（施主の指示には無く、ここで足した）
6. ダークの背景を `#000000` にする

## 強制

- **active**: core の単体テスト（閉じるボタンの当たり判定・題の上は部品でない・ダークの背景が `#000000`）、application の単体テスト（2x の環境でもモーダルは 1x）、ui-x11 の画素テスト（2x の環境でも 320 × 280・縁線・× の交点）
- **active**: Xvfb の実操作（gate-proofs 第 23 節）。× で閉じ、背景のドラッグで動く
- **planned**: WSLg での施主の目視（QLT-013）

## 結果

得られるもの:

- モーダルが枠の窓と同じ見た目の言葉（飾りなし・影なし）になる
- 4K でもモーダルは 320 × 280 で、場所を取らない

失うもの・残る穴:

- WM の閉じるボタン・最小化・Alt+ドラッグ以外の移動手段が無くなる。閉じるのは ×・Esc・Alt+F4
- 4K ではモーダルの字（12 px）が小さい。施主の指示どおり
- ダークの背景が黒になり、色見本の 8 番目（暗い灰色）が見分けにくい

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| モーダルも 2x のまま字だけ小さくする | 部品が大きく字が小さいと釣り合わない。施主は大きさそのものを指摘した |
| 題の帯（上の 40 px）だけを掴み所にする | 小さな窓で掴める所を狭める理由が無い。部品の無い所はどこでも掴めるほうが速い |
| 縁線を引かない | 飾りが無く背景が黒なので、暗い壁紙や黒いターミナルの上で窓の境が見えない |
