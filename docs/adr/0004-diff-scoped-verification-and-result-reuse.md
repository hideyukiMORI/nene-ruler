# ADR 0004 — 差分に必要な検証と成功結果の再利用

- 状態: 受理
- 日付: 2026-09-27
- Issue: #1
- 根拠: NeNe Nib で施主が 2026-09-20 に示した方針（Nib ADR 0021）の継承
- 影響する規則: QLT-001 / QLT-002 / QLT-007 / QLT-009 / QLT-010 / QLT-012 / GIT-004

## 決定

1. 完了条件は、差分の挙動と直接の依存・呼び出し元で起こり得る退行を検出する最小限の検証と、その記録・レビュー。各テストの必要性を説明できなければ実行しない。`make` の個別 target と `cargo test -p <crate> <name>` を使う
2. 検証済みの実装・テスト・関連依存・必要な環境条件が不変なら、担当・工程・文書・コミット SHA が変わっても成功結果を再利用する。PR に対象、退行の根拠、コマンドと結果、記録の場所、再利用元と不変性の根拠を書く
3. `make check` の全件検証は `REASON=<限定できない理由>` の明示指定でのみ実行する。指定なし・空の理由は実行前に拒否する
4. CI の必須 `check` は Git 規約、PR の検証記録の存在、差分の空白を確認する。製品テストは重ねて走らせない。記録の妥当性と入力の不変性はレビューで確認する
5. 差分が原因の失敗は修正する。無関係な既存失敗は根拠と別 Issue を記録して本件を継続する。成功するまでの反復で不安定さを隠すことを禁止する
6. 文書・コメント・規約だけならアプリの動作検証は不要。フック・開発ツールは変更した道具の正例・反例を短く確認する。coverage・`make prove` も関連する変更時に選ぶ

## 既存決定との関係

xi-tools の「`make check` が唯一の入口・CI は `make check` を呼ぶ」は本 ADR が置き換える。検査の判定基準は変えない。

## 検証

対象は `make check` の `REASON` 要求、`make ci` の欄の検査、文書整合。アプリのビルド・動作は無い。

## 却下

- 全件テストをローカルと CI の双方で繰り返す: 不変の入力を工程だけで測り直す
- 大規模な自動選定・キャッシュ基盤: この規模を超える
- 全検査を無効化する: 必要な退行確認と Git・検証記録の確認を失う
