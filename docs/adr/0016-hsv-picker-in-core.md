# ADR 0016 — カラーピッカーの色は整数の HSV で core が換算し、モーダルの編集状態が持つ

- 状態: 受理
- 日付: 2026-10-17
- Issue: #44
- 影響する規則: ARC-001 / ARC-003 / ARC-004 / RS-007 / RS-018。仕様 FR-010 / FR-012

## 文脈

2026-10-17、施主が「カラーピッカーが欲しい」とし、形は推しの「色相の帯＋彩度・明度の四角」に決めた。
インク色の正本は `RulerSettings` の `Rgb`（FR-012 で保存される）。ピッカーの位置は色相・彩度・明度で決まるが、RGB からは色相が一意に戻らない（灰・黒・白では色相が無い）。

core は `#![no_std]` で、`f64` の四則はあるが `round` / `floor` は無い（libm に依存しないため）。`as` での数値変換は禁止（RS-007）。

## 決定

**色相（0.1 度刻み 0〜3599）・彩度（千分率）・明度（千分率）の値型 `Hsv` を core に置き、RGB との換算を整数で行う。ピッカーの色はモーダルの編集状態（`ModalSession::picker`）が持ち、押すたびにインク色を `Hsv::to_rgb` で決めて保存する。**

1. 色相を 1 度刻みにすると、`#FB8C00` の往復で緑が 140 → 138 と 2 ずれた。0.1 度刻みでプリセット 8 色が ±1 以内で戻る
2. `RulerIntent::PickShade { saturation, value }` と `RulerIntent::PickHue(hue)`。`RulerController` はいまのピッカーの色の一部だけを差し替えるので、黒まで落としても色相は残る
3. 位置 → 値の写像（`shade_at` / `hue_at`）と、値 → 印の位置（`shade_point` / `hue_y`）は `SettingsLayout` に置く。描く矩形と当たり判定と写像が 1 か所から出る（ARC-001）。四角や帯の外へ引いた位置は縁へ寄せる
4. 描画は cairo のグラデーション。四角は色相の純色に「左が白・右が透明」と「上が透明・下が黒」を重ねる。HSV の彩度と明度はどちらも RGB で線形なので、重ねた色は `Hsv::to_rgb` と一致する（±数段の丸め）。帯は 6 区間の純色を区切りにした線形のグラデーション
5. 押したまま引くと追いかける。引いている間、毎回インク色を保存する

## 強制

- **active**: core の単体テスト（原色・灰・黒の換算、プリセットの往復 ±1、範囲への収め方、位置 ⇄ 値の写像と縁への寄せ）、application の単体テスト（色相を保って黒を経由し、青に戻る・保存される・閉じていれば何もしない）、ui-x11 の画素テスト（四角の白・純色・黒、帯の赤）
- **active**: Xvfb の実操作（gate-proofs 第 28 節）
- **planned**: 施主の目視（QLT-013）

## 結果

得られるもの:

- 色見本と直接入力の間の色を、見て選べる
- 換算は core の整数だけで決定的。X も cairo も要らずにテストできる

失うもの・残る穴:

- 引いている間、動くたびに設定ファイルへ書く（小さいファイル 1 つを置き換えるだけで、速さの問題は見ていない）
- モーダルが 96 px 高くなった（320 × 376）
- 色相の精度は 0.1 度。往復で成分が 1 ずれる色がある

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 色相を 1 度刻みにする | プリセットの往復で成分が 2 ずれる（`#FB8C00` で実測） |
| `f64` で換算する | core に丸め関数が無く、`as` も書けない。整数で足りる |
| ピッカーの色を持たず、毎回インク色の RGB から HSV に戻す | 黒や灰を経由すると色相が 0 に戻り、帯を押し直さないと元の色に戻れない |
| 1 画素ずつ `Hsv::to_rgb` で塗る | 結果は同じで、約 2 万回の矩形の塗りになる。グラデーションで足りる |
