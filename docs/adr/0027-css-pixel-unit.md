# ADR 0027 — 単位を戻し、物理画素と CSS 画素（dpi / 96 で割った値）を切り替える

- 状態: 受理
- 日付: 2026-10-19
- Issue: #100
- 影響する規則: ARC-001 / ARC-004 / ARC-009。仕様 FR-004 / FR-007 / FR-008 / FR-010 / FR-012 / FR-016。ADR 0012 の決定 1・4 を置き換える（決定 2・3 と mm / in を置かない理由はそのまま）。ADR 0006 の `unit` の鍵を戻す

## 文脈

定規はいつも物理画素を綴る（ADR 0012）。ところがブラウザの開発者ツールが示す要素の幅や高さは **CSS 画素**で、
150% のデスクトップ（144 dpi）では物理画素の 1/1.5 になる。施主は 2026-10-19 に「ブラウザの開発モードで計測されるピクセル数とスイッチできるようにしないとダメ」とした。

ADR 0012 が単位を外した理由は、mm / in の換算の元が EDID のミリ寸法で信用できないことだった。
CSS 画素の換算の元は別で、**デスクトップの dpi** である。

- Windows: ブラウザは `GetDpiForMonitor` の dpi から `devicePixelRatio` を決める。`WindowsScreenMetrics::desktop_dpi` が同じ値を読む（ADR 0021）
- X11: Chromium も Firefox も `Xft.dpi` を見る。無ければ 96（1 倍）。`Display` がルート窓の `RESOURCE_MANAGER` から同じ値を読む（ADR 0011）
- どちらも `Environment::desktop_dpi` として既に application に届いている。`RandR` のミリ寸法から出した dpi は、ブラウザが見ないので CSS 画素には使わない（UI の倍率の第二の元ではある・ADR 0011）

ブラウザのズーム（Ctrl + +）は外から分からない。ズーム 100% の値だけが一致する。

## 決定

**単位 `Unit`（core）を `px` / `CSS px` の閉じた集合として戻す。CSS 画素は物理画素 ÷（デスクトップの dpi / 96）で、dpi が無ければ 1 倍。整数でなければ小数 1 桁で綴る。mm / in は戻さない。**

1. `Unit { Px, CssPx }`・`DevicePixelRatio`（dpi を持ち、`css_tenths` で 10 分の 1 CSS 画素の整数に換算・`describe` で `1 CSS px = 1.5 px`）・`Measure`（単位と比の組）を core に置く。`LengthText` は `Measure` で綴り、整形はここだけ（ARC-001）
2. 幅・高さ・両方（`W × H CSS px`）・短い形（`W×H`）のすべてが同じ `Measure` で換算される。表示とコピーは同じ文字列のまま（FR-007）。小数は四捨五入で 1 桁（`266.7 CSS px`）、整数なら小数を書かない（`160 CSS px`）
3. `RulerSettings::unit` が設定の一部で、`RulerIntent::ChooseUnit` で変わり、保存される（FR-012）。比は起動時に `Environment::desktop_dpi` から一度だけ決める（ARC-004）
4. モーダルに「Unit」の段（`px` / `CSS px` のボタン）を戻し、右に換算の説明 `1 CSS px = 1.5 px` を出す。モーダルは 48 px 高くなる（320 × 424）
5. 設定ファイル v1 は `unit = px` / `unit = css_px` を `modal_theme` の次に書く。読むときは `unit` が無ければ `px`（1.0.0 のファイル）、以前の `mm` / `in` は `px`、それ以外は `Malformed`。版は上げない
6. 目盛の間隔・枠の大きさ・UI の倍率は物理画素のまま（FR-003 / FR-016）。CSS 画素は数字の綴りだけに効く

## 強制

- **active**: core の単体テスト（144 dpi で 400 px → `266.7 CSS px`・240 px → `160 CSS px`・96 dpi と dpi 無しで 1 倍・`describe` の 1 / 1.25 / 1.5 / 1.75 / 2・モーダルの単位の段の当たり判定と 320 × 424）、application の単体テスト（`ChooseUnit` で表示とコピーが `266.7 CSS px` になり保存される・`RandR` の dpi では換算しない・説明文）、settings-file の単体テスト（`unit = css_px` の往復・`unit` 無しは `px`・`mm` / `in` は `px`・`unit = cm` は `Malformed`）、ui-x11 の画素テスト（単位のボタンの選択色・説明文の文字・320 × 424）
- **active**: ui-win32 は `cargo clippy --target x86_64-pc-windows-gnu` で型が合うことまで。画素は施主の Windows で見る
- **planned**: 施主の Windows（150%）でブラウザの開発者ツールと突き合わせる（QLT-013）。記録は gate-proofs 第 49 節

## 結果

得られるもの:

- ブラウザの開発者ツールと同じ数字で測れる。Windows の 125% / 150% / 175% / 200% はどれも dpi から正確に決まる
- 換算の元が見えるので、合っていないときに何が違うか分かる（説明文が `1 CSS px = 1 px` なら dpi が取れていない）

失うもの・残る穴:

- ブラウザのズームが 100% でないときは合わない。手動の上書き（倍率を選ぶ段）は作らない。要るなら次の Issue
- 複数のモニタで dpi が違うとき、比は主モニタ（Windows）か `Xft.dpi`（X11）の 1 つだけ。定規が乗っているモニタの dpi ではない
- WSLg は `Xft.dpi` を置かないので、CSS px を選んでも物理画素と同じ数になる。説明文がそれを示す
- 小数 1 桁は丸めで、開発者ツールの `266.67` とは最後の桁が違う
- 数字が長くなる（`266.7 CSS px` は 12 文字）ので、詰めた表示・線を消した表示に切り替わる枠の大きさが px のときより大きい。判定は文字数から出るので壊れはしない

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| mm / in も一緒に戻す | ADR 0012 の理由（EDID のミリ寸法が信用できない・主画面が 0 mm）は変わっていない |
| 比を `RandR` のミリ寸法の dpi からも決める（UI の倍率と同じ順） | ブラウザは見ない値で、CSS 画素の定義から外れる。UI の倍率は見た目の問題なので近似でよいが、ここは数字の正しさの問題 |
| 倍率を手で選ぶ段（100% / 125% / 150% / …）を置く | dpi から正確に決まるものを人に選ばせると、間違った数字を出す経路が増える。ズームのためなら、ズームの値そのものを入れる別の設計が要る |
| 小数 2 桁で綴る | 枠の数字が長くなり、小さな枠で詰めた表示に早く切り替わる。10 分の 1 画素より細かい差は目で測れない |
| `css px` と小文字で綴る | 仕様の語は CSS 画素で、ブラウザの文書も CSS pixel。ボタンと数字で同じ語 `CSS px` を使う |
| 単位を設定に保存せず起動ごとに px に戻す | ブラウザの計測に使う人は毎回 CSS px に切り替えることになる。設定はすべて保存する（FR-012） |
