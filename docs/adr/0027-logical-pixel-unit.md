# ADR 0027 — 単位を戻し、物理画素と論理画素（dpi / 96 で割った値）を切り替える

- 状態: 受理（決定 7 の目盛の間隔は改訂 → [0028](0028-text-in-logical-pixels-and-ticks-follow-the-unit.md)、決定 4 の「比は起動時に一度だけ」は置換 → [0029](0029-dpi-of-the-monitor-under-the-ruler.md)）
- 日付: 2026-10-19
- Issue: #100
- 影響する規則: ARC-001 / ARC-004 / ARC-009。仕様 FR-004 / FR-007 / FR-008 / FR-010 / FR-012 / FR-016。ADR 0012 の決定 1・4 を置き換える（決定 2・3 と mm / in を置かない理由はそのまま）。ADR 0006 の `unit` の鍵を戻す

## 文脈

定規はいつも物理画素を綴る（ADR 0012）。ところがブラウザの開発者ツールが示す要素の幅や高さは **CSS 画素**で、
150% のデスクトップ（144 dpi）では物理画素の 1/1.5 になる。施主は 2026-10-19 に「ブラウザの開発モードで計測されるピクセル数とスイッチできるようにしないとダメ」とした。

この「物理画素 ÷ 拡大率」の数は分野ごとに呼び名が違うだけで同じものである。Web の CSS px、Windows の DIP（device-independent pixel）、Android の dp、Apple の point。
施主は Web 以外の人にも通じる語として **論理画素（logical px）**を選び、対になる語として物理画素を **physical px** とした（2026-10-19）。

ADR 0012 が単位を外した理由は、mm / in の換算の元が EDID のミリ寸法で信用できないことだった。
論理画素の換算の元は別で、**デスクトップの dpi** である。

- Windows: ブラウザは `GetDpiForMonitor` の dpi から `devicePixelRatio` を決める。`WindowsScreenMetrics::desktop_dpi` が同じ値を読む（ADR 0021）
- X11: Chromium も Firefox も `Xft.dpi` を見る。無ければ 96（1 倍）。`Display` がルート窓の `RESOURCE_MANAGER` から同じ値を読む（ADR 0011）
- どちらも `Environment::desktop_dpi` として既に application に届いている。`RandR` のミリ寸法から出した dpi は、ブラウザが見ないので論理画素には使わない（UI の倍率の第二の元ではある・ADR 0011）

ブラウザのズーム（Ctrl + +）は外から分からない。ズーム 100% の値だけが一致する。

枠の数字の文字数は「全部描く／詰める／線を消す」の切り替え（ADR 0017 / 0018）を決める。文字数を変えた場合の、目盛を保てる枠の下限を実測した:

| 枠の数字 | 全部描ける最小の枠（幅 400 のとき） | 線まで消える幅 |
| --- | --- | --- |
| `400 px`（6 文字） | 幅 112・高さ 120 | 79 未満 |
| `400 physical px`（15 文字） | 幅 174・高さ 182 | 149 未満 |

## 決定

**単位 `Unit`（core）を物理画素 / 論理画素の閉じた集合として戻す。論理画素は物理画素 ÷（デスクトップの dpi / 96）で、dpi が無ければ 1 倍。整数でなければ小数 1 桁で綴る。モーダルと設定ファイルは `Physical px` / `Logical px` で対にし、枠の数字は `400 px` / `266.7 logical px`。mm / in は戻さない。**

1. `Unit { Physical, Logical }`・`DevicePixelRatio`（dpi を持ち、`logical_tenths` で 10 分の 1 論理画素の整数に換算・`describe` で `1 logical px = 1.5 physical px`）・`Measure`（単位と比の組）を core に置く。`LengthText` は `Measure` で綴り、整形はここだけ（ARC-001）
2. 幅・高さ・両方（`W × H logical px`）・短い形（`W×H`）のすべてが同じ `Measure` で換算される。表示とコピーは同じ文字列のまま（FR-007）。小数は四捨五入で 1 桁（`266.7 logical px`）、整数なら小数を書かない（`160 logical px`）
3. 枠の数字で物理画素は裸の `px`。この製品の `px` は仕様で物理画素と定めてあり（FR-003 / FR-016）、目盛の数字も裸の `px` なので、枠の数字だけ `physical px` と書くと目盛と食い違う。文字数が 2.5 倍になると目盛を保てる枠の下限が上の表のとおり上がり、単位を切り替えない人にも効く
4. `RulerSettings::unit` が設定の一部で、`RulerIntent::ChooseUnit` で変わり、保存される（FR-012）。比は起動時に `Environment::desktop_dpi` から一度だけ決める（ARC-004）
5. モーダルに「Unit」の段（`Physical px` / `Logical px` のボタン・幅 96）を戻し、その下の行に換算の説明 `1 logical px = 1.5 physical px` を出す。モーダルは 72 px 高くなる（320 × 448）
6. 設定ファイル v1 は `unit = physical_px` / `unit = logical_px` を `modal_theme` の次に書く。読むときは `unit` が無ければ物理画素（1.0.0 のファイル）、以前の `px` / `mm` / `in` も物理画素、それ以外は `Malformed`。版は上げない
7. 目盛の間隔・枠の大きさ・UI の倍率は物理画素のまま（FR-003 / FR-016）。論理画素は数字の綴りだけに効く

## 強制

- **active**: core の単体テスト（144 dpi で 400 px → `266.7 logical px`・240 px → `160 logical px`・96 dpi と dpi 無しで 1 倍・`describe` の 1 / 1.25 / 1.5 / 1.75 / 2・物理画素の綴りが `400 px` のまま・モーダルの単位の段の当たり判定と 320 × 448）、application の単体テスト（`ChooseUnit` で表示とコピーが `266.7 logical px` になり保存される・`RandR` の dpi では換算しない・説明文）、settings-file の単体テスト（`unit = logical_px` の往復・`unit` 無しは物理画素・`px` / `mm` / `in` は物理画素・`unit = cm` は `Malformed`）、ui-x11 の画素テスト（単位のボタンの選択色・説明文の文字・320 × 448）
- **active**: ui-win32 は `cargo clippy --target x86_64-pc-windows-gnu` で型が合うことまで。画素は施主の Windows で見る
- **planned**: 施主の Windows（150%）でブラウザの開発者ツールと突き合わせる（QLT-013）。記録は gate-proofs 第 49 節

## 結果

得られるもの:

- ブラウザの開発者ツール・Windows の DIP と同じ数字で測れる。Windows の 125% / 150% / 175% / 200% はどれも dpi から正確に決まる
- 換算の元が見えるので、合っていないときに何が違うか分かる（説明文が `1 logical px = 1 physical px` なら dpi が取れていない）
- 既定（物理画素）の見た目と、目盛を保てる枠の下限は今までと同じ

失うもの・残る穴:

- 枠の数字は完全には対でない（`400 px` と `266.7 logical px`）。対はモーダルの段と説明文が示す
- ブラウザのズームが 100% でないときは合わない。手動の上書き（倍率を選ぶ段）は作らない。要るなら次の Issue
- 複数のモニタで dpi が違うとき、比は主モニタ（Windows）か `Xft.dpi`（X11）の 1 つだけ。定規が乗っているモニタの dpi ではない
- WSLg は `Xft.dpi` を置かないので、論理画素を選んでも物理画素と同じ数になる。説明文がそれを示す
- 小数 1 桁は丸めで、開発者ツールの `266.67` とは最後の桁が違う
- 論理画素を選んだときは数字が長く（`266.7 logical px` は 16 文字）、詰めた表示・線を消した表示に切り替わる枠の下限が物理画素のときより大きい（幅 181・高さ 189）。判定は文字数から出るので壊れはしない

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| mm / in も一緒に戻す | ADR 0012 の理由（EDID のミリ寸法が信用できない・主画面が 0 mm）は変わっていない |
| 比を `RandR` のミリ寸法の dpi からも決める（UI の倍率と同じ順） | ブラウザは見ない値で、論理画素の定義から外れる。UI の倍率は見た目の問題なので近似でよいが、ここは数字の正しさの問題 |
| 倍率を手で選ぶ段（100% / 125% / 150% / …）を置く | dpi から正確に決まるものを人に選ばせると、間違った数字を出す経路が増える。ズームのためなら、ズームの値そのものを入れる別の設計が要る |
| 小数 2 桁で綴る | 枠の数字が長くなり、小さな枠で詰めた表示に早く切り替わる。10 分の 1 画素より細かい差は目で測れない |
| 語を `CSS px` にする | 最初の実装の語。Web の人にしか通じず、Windows の開発者や Store の利用者には DIP の方が近い。施主が 2026-10-19 に一般名の `logical px` へ改めた |
| 語を `dip` / `dp` / `pt` にする | Windows / Android / Apple の固有の語。`pt` は印刷の 1/72 インチと衝突する |
| 枠の数字も `400 physical px` / `266.7 logical px` で完全に対にする | 目盛を保てる枠の下限が幅 112・高さ 120 から幅 174・高さ 182 に上がり、単位を切り替えない人の 400 × 150 の枠でも目盛が消える。施主が「完全でなくていい」とした（2026-10-19） |
| 単位を設定に保存せず起動ごとに物理画素に戻す | ブラウザの計測に使う人は毎回切り替えることになる。設定はすべて保存する（FR-012） |
