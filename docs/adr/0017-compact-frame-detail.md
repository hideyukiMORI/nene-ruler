# ADR 0017 — 数字が読めない小さな枠では、目盛を消して中央に W × H px を出す

- 状態: 受理
- 日付: 2026-10-17
- Issue: #48
- 影響する規則: ARC-001 / FR-003 / FR-004 / FR-007 / FR-014

## 文脈

2026-10-17、施主が「枠が小さくなると、目盛などで幅の数値が見えなくなる。目盛で数値が見えなくなる大きさになった場合は、目盛を非表示にして枠線だけにし、中央に `100px * 20px` のように出さないとダメかも」とした。

`FrameLayout` は大きさに関係なく、目盛・目盛の数字・幅と高さの数字・通知を同じ置き場に描いていた。幅の数字は上辺の目盛の数字の下の中央、高さの数字は左辺の目盛の数字の右に置くので、狭い・低い枠では左辺の数字や右辺・下辺の目盛と重なる。

## 決定

**`FrameLayout::fitted` が、幅と高さの数字が「左辺の数字の右・右辺と下辺の主目盛の内側」に収まり互いに重ならないかを文字数の見積りから判定し、収まらなければ詰めた表示（`FrameDetail::Compact`）にする。詰めた表示では目盛・目盛の数字・通知を描かず、枠の中央に `W × H px` を 1 行で出し、押すとその文字列をコピーする。**

1. 数字は閉じた集合 `LengthLabel`（`Width` / `Height` / `Size`）。`HitTarget::Copy`・`RulerIntent::CopyText`・`CopyMark` はこれで受ける。全部描くときは `Width` と `Height`、詰めたときは `Size` だけ
2. `LengthText::size` が `100 × 20 px`（× は U+00D7）を綴る。表示とコピーは同じ文字列（FR-007）
3. 線・鉤括弧・ギア・線の帯は詰めても残す（移動と伸縮に要る）
4. 判定に使う文字数は、当たり判定と同じ見積り（1 文字 7 px・字の高さ 11 px）
5. 通知は枠の内側で切る（狭い枠で文が右へはみ出していた）

## 強制

- **active**: core の単体テスト（400 × 240 は全部・100 × 240 と 400 × 60 と 40 × 40 は詰める・幅を 1 px ずつ縮めると切り替わりは 1 回だけ・詰めると目盛と目盛の数字が 0 で中央が `Size` のコピー）、application の単体テスト（100 × 40 で `100 × 40 px` をコピー・通知を出さない）、ui-x11 の画素テスト（目盛の所が帯の薄いインクだけ・中央に字のインク）
- **planned**: 施主の目視（QLT-013）

## 結果

得られるもの:

- 小さい枠でも、大きさが 1 か所に読める形で出る
- 切り替えの判定と置き場が core の 1 か所にある

失うもの・残る穴:

- 詰めた表示では目盛が無いので、枠の中の位置は読めない
- 最小の大きさ（40 px）に近い枠では `W × H px`（約 70 px）が枠より広く、枠の外へはみ出す。最小の大きさは変えていない
- 字の幅は見積り。実際のフォントの幅との差で、切り替えが数 px ずれる

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 幅と高さを 2 行で中央に出す | 低い枠（高さ 20〜40 px）に 2 行は入らない。施主の例も 1 行 |
| 詰めても目盛だけは残す | 施主の指示は「目盛を非表示にして枠線だけ」。小目盛でも 4 px あり、40 px の枠では字と重なる |
| 字を小さくして収める | 9 px より小さい字は読めない。大きさで切り替えるほうが単純 |
